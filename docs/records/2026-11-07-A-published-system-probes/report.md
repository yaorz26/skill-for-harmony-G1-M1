## 小艺实际对话

使用设备上的小艺主对话页，发送前逐字核对 RichEditor 中的实际输入，等待回复后从布局中提取对应用户消息之后的回复。中文映射尝试及重开后的尝试使用新对话；重开通过 force-stop 后启动声明为可见且无额外权限要求的 VoicePcFreeAbility 完成。没有调用隐藏脚本执行器或绕过系统权限。

本轮共 7 笔 Skill 发现/调用尝试和 1 笔 Agent 发现尝试。完整固定输入与对应回复见[系统尝试](system-probes.json)。主要观察如下：

| 尝试 | 实际观察 | 判定 |
| --- | --- | --- |
| 英文注册名指定回显 | 首次拒绝请求；重开后明确回复没找到可用回显技能 | 未取得目标匹配或调用证据 |
| 普通中文回显、长度 | 回答标记文本或长度 5 | 内容可由模型直接生成，不能计为 Skill 执行 |
| 中文映射“G1M1文本回显” | 回答测试标记文本 | 没有脚本入口和上报的关联证据 |
| 中文映射“G1M1文本长度”，输入 `你好ABC😀` | 提及 conversion-tools，再回答长度 6 | 与本项目 UTF-16 长度 7 不一致，不能计为目标执行结果；不能据模型表述认定实际执行了代码 |
| 重开小艺后，明确要求 UTF-16 长度 | 回答 7，但称原技能不适用 | 数值正确仍不证明调用了目标 Skill |
| 点名 Skill Agent Demo / g1m1-skill-agent | 拒绝请求 | 无真实 Agent 连接、数据或回包证据；不据此认定组件实现错误 |

每次回复后查询 G1M1 相关 hilog，再只解析本应用 `[G1M1]` JSON 事件，没有观察到 system_skill_entered、system_result_reported 或 Agent 连接/收发阶段。搜索结果中出现测试标记或小艺对话摘要不计为本应用事件。无缓冲日志仅为辅助观察，不能单独证明没有调度，也不能据此确定故障原因。

另执行一笔明确标记为 in-app 的日志对照，应用 UI 正确回显 `G1M1-LOG-CONTROL-1107`，并取得同一 requestId 的完整五阶段事件。见[日志对照](logging-control.json)。这证明当时能采集到该应用的普通执行日志，不替代任何系统测试。

## 环境就绪校验

用户从发布窗口提供的校验步骤要求系统为 HarmonyOS 7、小艺为 11.7.x 或以上，并以主对话快捷方式出现“Skill真机测试中”作为就绪标志。官方[真机测试说明](https://developer.huawei.com/consumer/cn/doc/service/skill-real-machine-testing-0000002592771628)的发布示意图也包含设备支持校验步骤。本轮读回的系统和小艺版本符合用户提供的版本门槛。

重开后的新对话页，实际快捷方式为：小艺搜索、开始新慧记、小艺翻译、小艺Work、帮我写作、PPT生成、窗口协同。观察到的快捷方式与主对话布局没有“Skill真机测试中”。见[局部截图](quick-actions.png)和[就绪检查](readiness.json)。这是对当前客户端、当前时刻的观察，不是所有 PC 均不支持的结论，也没有证明发布被平台拒绝。

小艺“应用服务管理”能看到 Skill Agent Demo，页面“允许小艺控制”为开启状态。设备上新旧两个包名均已安装且显示名称相同，本轮没有独立核对这个设置项绑定哪个包名，因此不能将它当作新包名的完整授权证据；应用控制开关本身也不等于测试 Skill 已加载。
