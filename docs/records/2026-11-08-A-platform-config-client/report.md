# A：平台配置、客户端更新与真实调用复测

日期：2026-11-08（北京时间）。承接[平台只读核对](../2026-11-08-A-platform-readback/report.md)。在用户授权修改配置并继续真机验证后完成以下工作；本轮没有修改应用实现或 D 的验收表。

## 当前结论

仍未验证小艺到应用 Skill 的真实调用。两个 Skill 已补齐 API 26 并重新发布，小艺已更新到应用市场提供的 11.7.9.300，但 MateBook 仍未出现平台定义的“Skill真机测试中”就绪入口。更新后的回显、长度请求均无应用 `[G1M1]` 执行事件，S01/S02 不能标通过。

当前优先待华为侧确认的是该 PC 型号、系统构建与账号是否已获得主对话 Skill 测试能力，以及应用 Skill 在当前主对话测试发布链路中的发现条件。这是基于现象的排查方向，尚无客户端内部资格判定或服务端拒绝原因，不能断言所有鸿蒙 PC 均不支持。

## 更正 availableOn 的判断

通用开发规范列有 pc，但当前平台加载的配置组件只提供 cloud / cloudSandbox，主对话发布处理也使用这两个值。保持其他配置不变，分别尝试 `[cloud, pc]` 与 `[pc]`，两次 saveSkillConfig 均返回 HTTP 400、code=100000112、desc=`param error!`，查询确认原配置未被改变。

因此保留当前平台接受的 `[cloud]`；不能把“没有 pc”直接写成唯一根因，也不能声称已经修复 PC 发现能力。两项失败尝试只说明当前保存入口拒绝这些参数组合，不代表整个产品从未支持 PC。

## HAP 导入与脚本注册核对

用与设备安装包一致的签名 HAP 经“批量导入”重新解析，响应 code=0、success=2、failed=0，分别生成回显和长度 ZIP 记录。这证明 HAP 导入后出现 ZIP 名称是平台的正常转换行为，先前 ZIP 附件名称不能证明上传选错。

这次导入产生两个新的未发布副本，配置查询初始 availableOn 为空、API 版本未设置；没有替换原来的有效测试发布。核对完成后已仅删除本轮生成的两个副本，平台列表恢复为原来的 6 条记录。

HAP 的 module.json 确认包含正确包名、API 26、2in1 和两项 skillProfiles，绑定 EntryAbility 及对应脚本路径；编译后的 ets/modules.abc 含两个脚本名、completeArkTSScriptInApp 和执行日志标记。该静态证据不能替代系统调度成功证据，详见[打包注册核对](hap-registration.json)。

## 小艺复测

所有请求均通过原生小艺输入框输入并回读核实后发送，回复从设备 UI 布局提取；同时采集 `hilog -x -e G1M1`。日志中无 `[G1M1]` 只能说明这些采集没有观测到应用事件，不能单独证明客户端从未尝试调度。

| 条件 | 请求 | 观察 |
| --- | --- | --- |
| API 26 重新发布后，旧小艺 | 指定长度 Skill 计算“你好ABC😀”的 UTF-16 长度 | 表示 Skill 不在可用列表，随后自行计算；0 个应用事件 |

| 关闭深度思考后，新会话 | 指定 UTF-16 长度 | 自行回答 7；0 个应用事件，不能把答案正确视为真实调用 |

小艺信息页的“使用小艺本地 AI 处理对话”开关显示关闭。没有修改该开关或扩大隐私权限。“深度思考”本轮为排查临时关闭，复测后已恢复原来的开启状态；它影响回复方式，未解决 Skill 发现问题。

四项原始输入、回复摘录及采集时间见[设备复测](device-probes.json)。页面中的“已完成”仅为小艺会话状态，不是应用回包证据。
